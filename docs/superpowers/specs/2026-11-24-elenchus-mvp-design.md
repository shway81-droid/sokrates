# 수업 후 정리 엘렌코스 MVP 설계

2026-11-24 · 근거 문서: `수업 후 정리 엘렌코스 PRD.md` (2026-11-23)

이 문서는 PRD를 실제로 만들 수 있게 구체화한 것입니다. PRD와 다른 점은 **[변경]**, 대화에서 사용자님이 정한 것은 **[결정]**, 설계자가 정한 것은 **[설계자 판단]**으로 표시했습니다.

## 1. 의도와 이유

- 수업이 끝날 때 학생이 "오늘 배운 3가지"를 말하면, AI가 그중 흔들리는 생각 **1개에만** 반례 질문을 최대 3번 던집니다. 학생은 그 질문을 받으며 스스로 다시 생각합니다.
- 이 도구가 하는 일은 교사의 "되묻기"를 대신 맡는 것입니다. 성공했는지는 학생 점수가 아니라 두 가지로 봅니다.
  - 교사가 되묻는 부담이 줄었는가
  - 학생이 오개념을 스스로 고쳤는가
- 소크라테스식 평가 6가지(엘렌코스, 모르는 친구, 오답 탐정, 왜 사다리, 문제 출제자, 반쪽 정답) 가운데 첫 번째입니다. 나머지 5가지도 같은 틀 위에 올릴 수 있게 만듭니다.

## 2. 목표 · 비목표 · 하면 안 되는 것

**목표**
1. 학생 1명의 정리활동이 5~7분 안에 끝납니다.
2. 범위는 **6·25 전쟁 주제 전체**이고, 자료는 **세 교과서(천재·아이스크림·비상)의 내용으로만 한정**합니다. AI는 교과서 밖의 지식을 쓰지 않습니다. 반례 질문은 그중에서도 **교사가 고른 교과서**의 내용 안에서만 나옵니다. **[결정]**
3. 결과는 판정 라벨 1개와 세 줄 정리(알게 된 것 / 다시 생각한 것 / 다음 시간 확인할 것)로 남습니다.
4. 다음 방법을 추가할 때 `methods/` 아래에 파일 하나만 더하면 되도록, 화면 틀과 데이터를 다시 쓸 수 있게 만듭니다. **[결정]**

**비목표**
- 학생 개별 로그인, 점수·평가 기록, 학생이 각자 기기로 AI와 직접 대화하는 기능
- 6·25 전쟁 밖의 주제나 다른 과목
- 다른 교사에게 배포하는 일(B안: 서버가 대신 API를 호출하는 방식)

**하면 안 되는 것** (기능이 돌아가도 이렇게 되면 실패입니다)
- AI가 정답이나 설명을 말해 버리는 것
- 화면에 "틀렸습니다", 점수, 빨간 X처럼 틀렸다는 표시가 나오는 것
- 고른 교과서에 없는 내용으로 반례를 던지는 것
- 학생 이름이나 답변이 어딘가에 저장되는 것
- 교과서 문장을 길게 그대로 옮겨 적는 것(배포할 때 저작권 문제가 생깁니다)

## 3. 제약 조건

- **실행 환경:** 교사 PC의 크롬에서 `index.html`을 **더블클릭하면 열려야 합니다.** 서버나 빌드 과정은 없습니다. 크롬은 `file://`로 연 페이지에서 `fetch`로 JSON을 읽지 못하게 막기 때문에, 데이터는 `.js` 파일에 담아 `<script>`로 불러옵니다.
- **화면:** 교실 TV에 띄워 3명이 함께 봅니다. 본문 글씨는 최소 32px, 질문 글씨는 그보다 크게 하고, 대비를 높입니다.
- **AI:** Claude API를 브라우저에서 직접 호출합니다. 키는 교사가 화면의 설정 칸에 넣으면 그 PC의 `localStorage`에만 저장됩니다. 채팅이나 코드 파일에는 키를 넣지 않습니다. **[결정: Claude]**
- **입력:** 입력 칸 하나에 교사나 학생 누구든 타이핑합니다. 음성 입력은 넣지 않습니다(소리가 외부 서버로 가기 때문입니다). **[설계자 판단]**
- **진행:** 화면은 한 번에 학생 1명을 다룹니다. "다음 학생" 버튼을 누르면 입력과 대화가 모두 지워집니다. 3명을 연달아 하든 하루에 1명씩 돌아가며 하든 같은 화면으로 됩니다. **[설계자 판단]**
- **말투:** AI 질문은 5학년이 아는 낱말로, 존댓말로, 1문장 40자 이내로 합니다.
- **개인정보:** 학생 이름은 받지 않습니다. 대화는 메모리에만 있고, 탭을 닫거나 "다음 학생"을 누르면 사라집니다. `localStorage`에는 API 키, 모델, 마지막으로 고른 교과서만 저장합니다.

## 4. 만드는 방법 (검토한 방법들)

| 방법 | 장단점 | 선택 |
|---|---|---|
| 1. HTML 한 파일에 전부 넣기 | 가장 빠릅니다. 하지만 다음 방법을 만들 때마다 파일을 통째로 복사해야 하고, 6·25 데이터가 여러 군데에 중복됩니다 | 탈락 |
| **2. 공통 틀 + 방법별 부품 폴더** | 화면 틀, API 호출, 출력 검사, 데이터를 6개 방법이 같이 씁니다. 처음에는 1번보다 조금 더 걸리지만, 나중에 B안으로 옮길 때 API 호출 부분만 바꾸면 됩니다 | **[결정]** |
| 3. 짬짬이 모노레포 + Supabase(B안)로 바로 시작 | 키가 노출되지 않습니다. 하지만 서버, 호출 횟수 제한, 비용 설계가 먼저 필요해서 내일 시범에는 맞지 않습니다 | 수요를 확인한 뒤로 미룹니다 |

| 교과서 | 핵심 차시 | 참고만 할 차시 |
|---|---|---|
| 천재(박기범) | 3단원 11차시, 12차시 | 3단원 01·08·10·14차시 중 6·25를 언급한 부분 |
| 아이스크림 | 3단원 10차시, 12차시 | 3단원 01·08·13·14차시 중 6·25를 언급한 부분 |

**구조**

```js

    ["북한군", "북한", "인민군"],
```

**규칙**
- `sources`에 고른 교과서가 들어 있는 개념과 오개념만 **반례 질문의 재료**로 씁니다. 맞는지 확인할 때는 전체 개념을 씁니다.
- 세 교과서 모두 "유엔군"이 아니라 "국제 연합군"으로 씁니다(확인함). 학생이 쓰는 말을 인정하기 위해 `synonyms`를 둡니다.
- 오개념은 AI가 초안을 만들고 교사가 검토합니다. `reviewed: false`인 항목이 하나라도 있으면 시작 화면에 "검토하지 않은 오개념이 N개 있어요"라고 작게 알립니다. 시범은 막지 않습니다. **[설계자 판단 — PRD는 "검토 뒤에만 쓴다"고 했으나, 검토 여부를 표시하는 방식으로 완화했습니다]**
- 쪽 번호는 실제 교과서에 인쇄된 쪽입니다. 차시 PDF의 장 번호가 아닙니다. 천재 교과서는 장 번호와 쪽 번호의 차이(offset)가 쪽마다 다르니 `classall/textbook/README.md` 표를 따릅니다.

## 7. 화면 흐름

한 학생의 활동은 아래 순서를 한 번 거칩니다.

0. **설정**(처음 한 번): API 키 입력, 모델 선택, "키 지우기" 버튼이 있습니다. 키가 없으면 다른 화면으로 넘어가지 않습니다.
1. **시작:** 방법(지금은 엘렌코스만 있음), 주제(6·25 전쟁), 교과서(천재/아이스크림/비상)를 고릅니다. 마지막으로 고른 교과서를 기억해 둡니다.
2. **배운 3가지:** 큰 입력 칸 3개를 채우고 [확인하기]를 누릅니다. 빈 칸이 있으면 넘어가지 않습니다.
3. **내용 확인:** 항목마다 ✓ 또는 "더 생각해 볼 것"이 표시되고, 반례 대상 1개가 강조됩니다. 바로 아래에 첫 질문이 나옵니다.
4. **반례 문답:** 질문 카드 1장, 답 입력 칸 1개, 진행 점(●○○)이 보입니다. 이전 질문과 답은 작게 위에 쌓입니다. 최대 3번까지 합니다.
5. **판정과 정리:** 판정 라벨 1개와 세 줄 정리가 나옵니다. 그 아래에 [복사] [인쇄] [다음 학생] 버튼이 있습니다.

화면 오른쪽 위에는 지난 시간(예: 4:12)을 작게 띄웁니다. 검증 지표 "7분 이내"를 재는 데 씁니다. **[설계자 판단]**
교사용 [바로 정리하기] 버튼도 둡니다. 시간이 모자라면 질문이 남아 있어도 판정으로 넘어갑니다. **[설계자 판단]**

## 8. AI 호출 설계

**누가 무엇을 정하는가**: 몇 번 물을지, 언제 끝낼지, 검사에 걸렸을 때 어떻게 할지는 **코드**가 정합니다. AI는 매번 정해진 JSON 하나만 돌려줍니다.

| 호출 | 언제 | AI에 보내는 것 | AI가 돌려주는 것 |
|---|---|---|---|
| ① 확인 | 3가지를 제출했을 때 | 전체 개념, 오개념, 같은 뜻 말, 고른 교과서 범위, 학생의 3가지 | `{"stage":"check","checks":["ok","ok","think"],"target":2,"mode":"counter","question":"…"}` |
| ② 다음 질문 | 학생이 답했을 때(1·2번째 답) | ①의 내용 + 지금까지의 대화 | `{"stage":"question","question":"…"}` 또는 일찍 판정할 수 있으면 `{"stage":"verdict",…}` |
| ③ 판정 | 3번째 답을 했을 때, 또는 [바로 정리하기]를 눌렀을 때 | ①의 내용 + 모든 대화 | `{"stage":"verdict","verdict":"strong|revisit|hold","summary":["…","…","…"]}` |

- `mode`는 세 가지 중 하나입니다.
  - `"counter"`: 오개념이 의심되어 반례로 묻습니다.
  - `"reason"`: 3가지가 모두 맞아 이유를 묻습니다.
  - `"retry"`: 6·25와 관계없는 입력이 있어 다시 말해 보게 합니다.
- **target을 고르는 순서** **[설계자 판단]**: 오개념이 의심되는 항목을 가장 먼저 고릅니다. 그런 항목이 없으면 관계없는 항목을 고릅니다. 둘 다 없으면 `reason`으로 갑니다. 오개념 항목과 관계없는 항목이 함께 있으면 오개념 항목을 target으로 고르고, 관계없는 항목은 "더 생각해 볼 것" 표시만 남깁니다.
- **`retry`의 흐름** **[설계자 판단]**
  - 다시 묻기도 3번 안에 셉니다.
  - 학생의 새 답은 그 대화 안의 답으로만 다룹니다. 원래 항목을 바꾸지 않습니다.
  - 새 답에 오개념이 보이면 다음 질문부터 `counter`로 바꿀 수 있습니다. 6·25 내용이지만 맞는 말이면 이유 질문으로 이어 갑니다.
  - 3번이 끝날 때까지 관계있는 내용이 나오지 않으면 판정은 `hold`입니다.
- **[변경]** PRD는 "3가지가 모두 맞으면 이유 질문 1개로 대신한다"고 했습니다. 이를 다음과 같이 구체화합니다. `mode:"reason"`일 때는 이유 질문 1개를 하고, 학생이 답하면 곧바로 ③ 판정으로 갑니다. 진행 점은 ●만 1개 보입니다.
- ③ 판정은 PRD의 판정 규칙을 따릅니다.
  - `strong`(튼튼한 생각): 학생이 교과서 근거를 대며 자기 생각을 지켰습니다.
  - `revisit`(다시 볼 생각): 학생이 스스로 허점을 인정했습니다.
  - `hold`(판정 보류): 어느 쪽도 아닙니다.
- 학생이 "모르겠어요"라고 하면 그것도 답 1번으로 셉니다. 그러면 AI는 다음 질문을 더 쉽게 냅니다.

**시스템 프롬프트에 넣을 규칙** (PRD 5절 + 추가)
1. 반례는 "고른 교과서 범위"로 표시된 개념과 오개념 안에서만 만듭니다. 근거가 없으면 "왜 그렇게 생각했나요?"라고 묻습니다.
2. 정답이나 설명을 말하지 않습니다. 질문은 1문장, 40자 이내, 물음표로 끝냅니다.
3. 5학년 어휘와 존댓말을 씁니다.
4. 맞는 지식에는 반례를 던지지 않습니다. 반례는 대상 1개에만 씁니다.
5. 같은 뜻 말 목록에 있는 표현은 맞는 것으로 봅니다. 맞춤법이나 띄어쓰기가 틀린 것은 문제 삼지 않습니다.
6. 6·25와 관계없는 입력(장난, 빈말)에는 반례를 던지지 않습니다. 그 항목은 "더 생각해 볼 것"으로 두고, "오늘 배운 것 중에서 하나 더 말해 볼까요?" 같은 다시 묻기를 합니다.
7. 세 줄 정리는 각 줄 40자 이내로, 학생이 한 말을 바탕으로 씁니다. 학생이 깨닫지 못한 정답을 정리에 적어 주지 않습니다. "다음 시간 확인할 것"은 질문 형태로 남깁니다.
8. 출력은 JSON 하나만 냅니다.
9. 맞는지 판단할 때도 주어진 데이터(세 교과서)만 근거로 삼습니다. AI가 따로 아는 지식은 쓰지 않습니다. 학생이 말한 내용이 사실일 수 있지만 세 교과서 어디에도 없으면(예: 특정 장군 이름), ✓나 "더 생각해 볼 것"을 붙이지 않고 `"outside"`로 표시합니다. 화면에는 "교과서 밖 이야기예요"라고 중립적으로 띄우고, 반례 대상으로 고르지 않습니다. 세 항목이 모두 `outside`이면 `retry`로 갑니다. **[설계자 판단]** 따라서 `checks` 값은 `ok`, `think`, `outside` 세 가지입니다.

**출력 검사 (`core/guard.js`)**
- 형식: JSON 파싱, `stage` 값, 필수 필드
- 질문: 40자 이내, 1문장, `?`로 끝남, 금지어("틀렸", "정답은", "오답")가 없음
- 세 줄 정리: 3줄, 각 줄 40자 이내
- 검사에 걸리면 1번 다시 호출합니다. 또 걸리면 질문은 기본 질문("왜 그렇게 생각했나요?")으로 바꾸고, 판정은 `hold`와 기본 세 줄로 바꿉니다. **[설계자 판단 — PRD는 바로 기본 질문으로 바꾸게 했으나, 수업 흐름을 지키려고 재시도를 1번 넣었습니다]**
- 네트워크나 키 오류가 나면 "AI 연결에 문제가 있어요. 선생님이 직접 물어봐 주세요."라고 띄웁니다. 입력한 내용은 지우지 않습니다.

## 9. 판정 화면 문구

| 판정 | 라벨 | 문구 |
|---|---|---|
| strong | 튼튼한 생각 | 반례에도 무너지지 않았어요. 근거가 있는 생각이에요. |
| revisit | 다시 볼 생각 | 스스로 허점을 찾았어요. 다음 시간에 확인해 봐요. |
| hold | 판정 보류 | 선생님과 더 이야기해 봐요. |

세 라벨 모두 따뜻한 색을 씁니다. 빨간색·X 표시·점수는 쓰지 않습니다.
