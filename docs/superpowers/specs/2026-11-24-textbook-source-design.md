# 교과서 원문으로 판단하기 + '교과서 밖' 좁히기 — 짧은 설계

## 왜
학생이 교과서에 있는 말을 해도 '교과서 밖'으로 나오는 일이 있다.
예: 천재교과서 4차시 130쪽 "수많은 사람이 죽거나 다쳤고"를 학생이 말했는데 교과서 밖으로 나왔다.
AI는 교과서를 줄여 만든 개념 문장 94개만 보고 판단하는데, 줄이면서 빠진 내용은 모두 '교과서 밖'이 된다.
요약을 아무리 다듬어도 이 구조에서는 다시 생긴다.

## 목표
- 오늘 차시 교과서에 있는 내용은 표현이 조금 달라도 맞음(✓)으로 판단한다.
- 확인이 안 되는 말이라도 오늘 주제와 관계있으면 '교과서 밖'으로 몰아세우지 않는다.

## 하지 않을 것
- 교과서 원문을 GitHub에 올리지 않는다. 원문은 선생님 PC에만 둔다.
- 반례 질문은 지금처럼 교과서에 있는 개념과 오개념으로만 만든다. AI가 따로 아는 지식은 쓰지 않는다.
- 원문이 없는 PC에서도 앱은 지금처럼 동작해야 한다.

## 접근 (사용자님이 1+2를 고름)
1. **원문 근거:** 오늘 차시 교과서 본문을 AI에게 함께 준다. — 채택. 오판의 원인 자체를 줄인다.
2. **'교과서 밖' 좁히기:** '교과서 밖'은 오늘 주제와 관계없는 말에만 쓴다. 관계있지만 확인이 안 되면 부드러운 표시를 쓴다. — 채택. 남는 빈틈이 학생에게 상처가 되지 않게 한다.
3. **선생님이 표시 바꾸기:** — 이번에는 하지 않는다. 필요하면 나중에 더한다.

## 설계
- **원문 파일**
  - `tools/build_local_texts.py`(커밋함)가 `work/3/<교과서>/<차시>.txt`를 읽는다.
  - 읽은 내용으로 `app/local/texts.js`를 만든다. 이 파일은 `.gitignore`로 커밋하지 않는다.
  - 파일 안에서 `window.SOKRATES_TEXTS = { chunjae: { "3-4": "…" }, … }`를 정한다.
  - `index.html`과 `tests/live.html`이 이 파일을 불러온다. 파일이 없으면 그냥 넘어간다.
- **AI에게 주는 내용**
  - 오늘 차시(`lessonId`)의 원문이 있으면 시스템 프롬프트 뒤에 `[오늘 차시 교과서 원문]` 블록으로 붙인다.
  - 같은 차시 동안 반복해서 보내는 비용을 줄이려고 프롬프트 캐시(`cache_control`)를 단다.
  - 단원 마무리나 원문이 없는 차시는 지금과 같다.
- **판단 규칙**
  - 맞는지는 원문과 [전체 개념]을 근거로 판단한다.
  - 표현이 달라도 원문과 뜻이 같으면 "ok"로 본다.
  - 반례는 지금처럼 [반례에 쓸 수 있는 범위]에서만 만든다.
- **확인 표시 값**

  | 값 | 화면 글 | 쓰는 경우 |
  |---|---|---|
  | `ok` | ✓ | 원문이나 개념과 맞음 |
  | `think` | 더 생각해 볼 것 | 오개념이 의심됨 |
  | `unsure` (새 값) | 교과서에서 함께 찾아봐요 | 오늘 주제와 관계있지만 원문과 개념에서 확인이 안 되고, 어긋나지도 않음 |
  | `outside` | 오늘 주제와 다른 이야기예요 | 장난, "모르겠다" 같은 주제와 관계없는 말 |

  - `unsure` 항목은 반례 질문 대상이 되지 않는다.
  - 질문 대상을 고르는 규칙에서 `unsure`는 `ok`처럼 다룬다. 이유 묻기 대상이 될 수 있고, 다시 말해 보게 하기 대상은 아니다.
- **점검:** 실제 AI 점검 사례에 "3·1 운동 때 많은 사람이 죽거나 다쳤다"(4차시, 기대: ok)를 넣는다. 원문이 있을 때 맞게 나오는지 확인한다.

## 비용과 개인정보
- 천재교과서 한 차시 원문은 약 4천~7천 자다. 한 번 부를 때 입력이 몇 배로 늘지만, 캐시로 반복 비용을 줄인다.
- 원문은 지금 학생 답과 마찬가지로 선생님 키로 Anthropic API에 보낸다.

## 만드는 사람에게 맡긴 것
- 원문 정리 방법: 쪽 표시는 남기고, 세로로 한 글자씩 끊긴 줄은 그대로 둔다.
- 캐시 블록을 나누는 위치.
- 테스트 세부.

## 점검하며 더한 것 (2026-11-24)
- 원문만 넘기자 AI가 오히려 깐깐해져 맞는 말을 "think"로 보는 일이 늘었다. 그래서 "think"는 학생 문장 안에 오개념의 틀린 주장이 실제로 들어 있을 때만 주도록 프롬프트를 좁혔다.
- 세 줄 정리가 검사에 걸려 기본값으로 대신하는 일이 잦았다(글자 수, 셋째 줄이 질문이 아님). 이를 줄이려고 두 가지를 바꿨다.
  - AI 응답 형식에서 세 줄을 칸 이름(learned, rethought, nextQuestion)으로 받는다. 앱 안에서는 지금처럼 세 줄 배열로 바꿔 쓴다.
  - 검사 사유에 몇 번째 줄이 몇 자인지 적어, 다시 낼 때 고칠 수 있게 했다.
- 남은 문제: "나라 곳곳에서 의병이 일어났다"처럼 맞는 말이 덜 자세하다는 이유로 "think"가 되는 일이 아직 있다(판정은 맞게 나옴).
