# 공통 틀 정리와 "2. 모르는 친구" 설계

2026-11-24 · 근거: `docs/elenchus-handoff.md`(엘렌코스 정리), 이번 대화

대화에서 사용자님이 정한 것은 **[결정]**, 설계자가 정한 것은 **[설계자 판단]**으로 표시했습니다. 표시가 없는 것은 엘렌코스 정리 문서에 이미 정해진 원칙입니다.

---

## 1. 의도와 이유

- 수업 말미에 "학생들이 오늘 배운 것을 정말 이해했을까?"를 확인하는 앱의 두 번째 방법입니다. 엘렌코스와 목적과 원칙이 같습니다. AI는 답을 주지 않고, 학생이 스스로 꺼내 보이게 합니다.
- **모르는 친구**: 학생이 오늘 배운 것을 친구에게 설명합니다. AI는 "잘 모르는 친구"가 되어 엉뚱한 질문을 2~3개 던지고, 학생은 다시 설명하거나 친구를 바로잡습니다. 남에게 설명할 수 있어야 이해한 것이라는 생각입니다.
- 엘렌코스가 "흔들리는 생각 하나를 반례로 흔드는" 방법이라면, 모르는 친구는 "설명할 수 있는지, 잘못 알아들은 친구를 바로잡을 수 있는지"를 봅니다.
- 이 방법을 붙이려면 먼저 공통 틀을 고쳐야 합니다. 지금 화면이 엘렌코스 모양에 묶여 있기 때문입니다. 3~6번 방법도 이 틀 위에 올라갑니다.

## 2. 목표 · 비목표 · 하면 안 되는 것

**목표**
1. 공통 틀이 방법마다 다른 화면을 받습니다. 3~6번은 `methods/`에 파일을 더하고 `index.html`에 스크립트 줄만 더하면 붙습니다.
2. 엘렌코스는 지금과 똑같이 동작하고 똑같이 보입니다. 단위 테스트 177개가 고치지 않은 채 그대로 통과합니다.
3. 모르는 친구가 학생 1명당 5~7분 안에 끝납니다.
4. 결과에서 선생님이 "어디는 설명할 수 있고, 어디가 비는지"를 질문마다 한눈에 봅니다.

**비목표**
- 3~6번 방법(오답 탐정, 왜 사다리, 문제 출제자, 반쪽 정답)
- 1·2단원 데이터
- 새 데이터(개념·오개념)를 만드는 일. 3단원 데이터를 그대로 씁니다.

**하면 안 되는 것**
- AI(친구)가 정답이나 설명을 말해 버리는 것. 친구의 반응 한마디로 답을 흘리는 것도 포함합니다.
- 학생이 잘못했다는 느낌을 주는 말. "틀렸", "정답은", "오답"을 쓰지 않습니다. 화면에 빨간색, X, 점수를 쓰지 않습니다.
- 고른 교과서의 오늘까지 배운 범위 밖 내용으로 질문하는 것
- 퀴즈형 질문(이름·숫자·연도를 맞히게 하는 질문)
- 선다형 질문(사용자님이 기각함)
- 학생 이름을 받거나 대화를 저장하는 것
- 엘렌코스의 동작이나 모양이 바뀌는 것

## 3. 제약

- 엘렌코스 정리 문서의 "지켜야 할 것"을 모두 따릅니다. 서버와 빌드 없이 동작하고, 스크립트는 `(function (root) { … })(this)` 모양으로 씁니다. 키는 [설정]에만 넣고, 교과서 원문은 커밋하지 않습니다. 데이터에 교과서 문장을 25자 이상 그대로 옮기지 않습니다.
- 질문은 "~요?"로 끝나는 존댓말이고, 40자 이내의 한 문장입니다. 친구 역할이어도 같은 검사(`SokGuard.checkQuestion`)를 씁니다. **[결정]**
- 기본 모델은 하이쿠(`claude-haiku-5-5`)이고, 캐시 구조는 엘렌코스와 같게 합니다(6장).
- **흐름은 코드가, 글은 AI가 맡습니다.** 질문 수, 끝내는 때, 검사에 걸렸을 때의 처리는 코드가 정합니다. AI는 정해진 JSON 하나만 돌려줍니다.

## 4. 접근 방법 (공통 틀)

| 방법 | 내용 | 장단점 |
|---|---|---|
| **1. 방법별 화면 + 공통 부품** **[결정]** | 방법이 자기 입력·문답·결과 화면을 가져옵니다. 설정·시작 화면, 위 막대, 타이머, [다음 학생]은 공통 틀에 둡니다. 질문 카드, 답 칸 같은 겹치는 조각은 공통 부품으로 씁니다. | 사다리 그림이나 틀린 곳 찾기처럼 모양이 크게 다른 화면도 붙습니다. 엘렌코스 화면 코드는 자리만 옮깁니다. |
| 2. 공통 상태 모양 | 모든 방법이 "입력 → 질문/답 반복 → 결과" 한 모양을 따르고, 화면은 공통 틀이 그립니다. | 코드가 가장 적습니다. 하지만 이번의 "질문마다 표시"부터 맞지 않습니다. |

사용자님이 1을 고르셨습니다. 엘렌코스 정리 문서도 같은 쪽을 추천했습니다.

## 5. 공통 틀 설계

### 5.1 파일

```
app/
  core/
    app.js            공통 틀: 설정·시작 화면, 위 막대, 타이머, 화면 전환, 방법 목록 (엘렌코스 화면 코드는 빠짐)
    parts.js          (새 파일) 공통 화면 부품. 브라우저 전용
    ui.js             기존 내보내기는 그대로 둠(테스트가 씀). 도움말 계산의 공통 함수만 더함(6.8)
  methods/
    elenchus.js       그대로 (문답 흐름. Node 테스트가 씀)
    elenchus-views.js (새 파일) app.js에서 옮긴 엘렌코스 화면 3개 + 방법 등록
    friend.js         (새 파일) 모르는 친구 문답 흐름, 프롬프트, 응답 형식, 검사, 결과 글
    friend-views.js   (새 파일) 모르는 친구 화면 3개 + 방법 등록
```

`index.html`의 스크립트 차례는 다음과 같습니다.
데이터 → `guard, topic, catalog, llm, ui, parts` → `elenchus.js, elenchus-views.js, friend.js, friend-views.js` → `app.js`

**[설계자 판단]** 화면 코드를 문답 흐름 파일과 나눕니다. 흐름 파일(`elenchus.js`, `friend.js`)은 Node 테스트에서 DOM 없이 불러와야 하기 때문입니다.

### 5.2 방법 등록

각 `*-views.js`는 마지막에 공통 목록에 자기를 넣습니다.

```js
(root.SokMethods = root.SokMethods || []).push({
  id: "friend",
  name: "모르는 친구",
  startHint: "친구의 질문은 고른 교과서에서 오늘까지 배운 내용으로만 나와요.",
  createSession,           // methods/friend.js 의 것
  views: { input(kit), talk(kit), result(kit) },  // 각각 DOM 요소 하나를 돌려줌
});
```

- `app.js`는 `root.SokMethods`를 읽습니다. 시작 화면 목록 차례는 스크립트 차례(엘렌코스 → 모르는 친구)입니다. 엘렌코스가 첫 항목이라 처음 여는 PC에서는 지금과 같습니다.
- `SokApp.registerMethod`는 남겨 둡니다(같은 목록에 넣음).
- **[설계자 판단]** 마지막으로 고른 정리 방법을 교과서·단원·차시처럼 localStorage(`sok.method`)에 기억합니다. 목록에 없는 값이면 첫 방법을 씁니다. 엘렌코스만 쓰던 PC는 지금과 같습니다.
- 시작 화면 "오늘 차시" 밑 안내 글은 방법의 `startHint`를 씁니다. 엘렌코스는 지금 글("반례 질문은 고른 교과서에서 오늘까지 배운 내용으로만 나와요.")을 그대로 넣습니다.

### 5.3 세션이 지킬 약속

공통 틀이 화면을 고르고 되돌아가는 데 쓰는 것만 정합니다. 나머지 상태 모양은 방법 마음대로입니다.

- `getState().phase`는 `"input" | "waiting" | "asking" | "error" | "done"` 중 하나입니다.
  - `input`이면 `views.input`, `done`이면 `views.result`, 나머지는 `views.talk`를 씁니다.
- `cancel()`: [다음 학생]이나 [처음으로]를 누를 때 부릅니다. 늦게 온 응답을 버립니다.
- `retry()`: 오류 뒤 [다시 시도]에서 부릅니다.
- `createSession({ topic, textbookId, lessonId, llm, sourceText })`: 지금과 같은 인자를 받습니다.

### 5.4 화면에 건네는 도구 (`kit`)

`app.js`가 화면 함수에 넘깁니다.

| 이름 | 하는 일 |
|---|---|
| `session` | 지금 학생의 세션 |
| `scope` | 시작 화면 선택(`Cat.resolve` 결과: topic, textbookId, textbookName, lessonLabel, contextTitle, lessonTitle, choice) |
| `act(promise)` | 세션 동작을 부른 직후 "생각하는 중" 화면을 그리고, 끝나면 결과나 문답 화면으로 넘깁니다. 지금의 `show("talk"); await p; after(s)`를 묶은 것입니다. |
| `toast(msg)`, `onEnter(fn)`, `copy(text)` | 지금 `app.js`의 도우미 그대로 |
| `elapsedText()` | 지난 시간 글자(예: "4:12") |
| `today()` | 날짜 글자 |
| `nextStudent()`, `openSettings()` | [다음 학생], [설정 확인] |

### 5.5 공통 부품 (`core/parts.js`, `SokParts`)

지금 `app.js`에 있는 것을 꺼내 함수로 만듭니다. 엘렌코스의 DOM 모양과 클래스 이름이 그대로 나오게 합니다.

| 부품 | 내용 |
|---|---|
| `goal(title)` | 맨 위 학습문제 상자 |
| `dots(done, max)` | 진행 점 ●○○ |
| `thinkingCard(who, dotsEl)` | "생각하는 중이에요" 카드 |
| `questionCard(who, dotsEl, question, extra)` | 질문 카드. `extra`는 질문 위에 붙는 작은 글(친구의 반응)이고, 엘렌코스는 쓰지 않습니다 |
| `answerArea(kit, { send, finish })` | 답 칸 + [바로 정리하기] [보내기]. Enter로 보내기 |
| `errorArea(kit)` | 오류 글 + [설정 확인] [다시 시도] |
| `helperBox(help)` | 접힌 선생님 도움말(지금 그대로) |
| `recordBox(lines)` | 접힌 문답 기록. 인쇄할 때 펼쳐짐 |
| `resultActions(kit, text)` | [복사] [인쇄] [다음 학생] |

`rethinkBox`와 판정 상자는 엘렌코스 전용이라 `elenchus-views.js`에 둡니다.

### 5.6 엘렌코스가 그대로인지 확인하는 법

- `cd app && node --test "tests/*.test.js"`: 기존 177개를 고치지 않고 통과해야 합니다(새 테스트는 더해짐).
- **화면 확인 페이지** `app/tests/views.html` **[설계자 판단]**: 키 없이 가짜 AI(정해 둔 JSON을 돌려줌)로 각 방법의 입력·문답·결과·오류 화면을 차례로 띄웁니다. 정리 전과 뒤의 엘렌코스 화면을 이 페이지와 실제 앱에서 비교합니다.
  - 정리 전에 지금 앱의 각 화면 HTML(`#screen`의 내용)을 찍어 둡니다. 정리 뒤 같은 입력으로 나온 HTML과 같아야 합니다.
  - 찍는 방법은 계획에서 정합니다.
- 실제 앱에서 엘렌코스 한 명을 끝까지 해 봅니다(사용자님 키, 하이쿠).

## 6. 모르는 친구 설계

### 6.1 화면 흐름

1. **시작**(공통): 정리 방법에서 "모르는 친구"를 고릅니다.
2. **설명 입력** **[결정: 한 칸 설명]**
   - 맨 위에 학습문제를 둡니다.
   - 제목은 "친구에게 오늘 배운 것을 설명해 볼까요?"이고, 그 아래 칸 하나(3줄 높이)를 둡니다. 자리 글은 "예) 오늘은 ~을 배웠어. ~해서 ~가 되었어." 같은 꼴입니다(문구는 구현 때 다듬음).
   - [보내기]를 누르면 바로 "생각하는 중" 화면으로 갑니다.
   - 빈 칸이면 보내지 않습니다. 글자 수 제한은 두지 않습니다.
3. **문답**
   - 위에 학생의 설명을 작게 보여 줍니다.
   - 질문 카드 이름은 "모르는 친구"입니다. 진행 점(최대 3)을 둡니다.
   - 질문 위에 친구의 짧은 반응을 한 줄 둘 수 있습니다(6.4).
   - 지난 문답은 엘렌코스처럼 카드 위에 쌓입니다.
   - 답 칸, [바로 정리하기], [보내기]가 있습니다.
4. **결과** **[결정: 질문마다 표시]**

```
[학습문제] 6·25 전쟁의 과정과 피해
나의 설명: 북한이 쳐들어와서 …
1. 정전이 뭐예요?               → 잘 설명했어요
2. 그럼 군인들만 다친 거예요?    → 친구를 바로잡았어요
3. 그럼 전쟁은 1953년에 끝났어요? → 함께 더 알아봐요
친구의 한마디: 덕분에 휴전선이 왜 있는지 알았어요!
다음 시간 확인할 것: 정전과 종전은 어떻게 다를까요?
▸ 선생님 도움말 (접힘, '함께 더 알아봐요'가 있을 때만)
▸ 문답 기록 (접힘)
[복사] [인쇄] [다음 학생]
```

- 표시는 답한 질문에만 붙습니다. [바로 정리하기]로 끝나 답하지 않은 마지막 질문은 결과에 나오지 않습니다(문답 기록에도 넣지 않음).
- 표시 색은 차분하게 합니다. 엘렌코스 확인 표시와 같은 계열(초록·청록·호박색)을 쓰고, 빨간색은 쓰지 않습니다.

### 6.2 질문의 종류 **[결정: 섞기]**

| 종류(`kind`) | 하는 일 | 예 |
|---|---|---|
| `meaning` 뜻·까닭 묻기 | 학생 설명에 나온 낱말의 뜻이나 일의 까닭을 순진하게 묻습니다. **교과서에 그 뜻이나 까닭이 나오는 것만** 묻습니다 **[설계자 판단]** | "정전이 뭐예요?", "왜 중국에서 정부를 만들었어요?" |
| `more` 더 말해 달라기 | 설명이 한두 낱말로 짧을 때 조금 더 말해 달라고 합니다 **[설계자 판단]** | "그래서 어떻게 되었는지 더 알려 줄래요?" |
| `retry` 다시 말해 보기 | 설명이 오늘 주제와 관계없거나 "몰라요"뿐일 때, 오늘 배운 것 하나를 말해 보게 합니다 **[설계자 판단]** | "오늘 무엇을 배웠는지 하나만 알려 줄래요?" |
| `mixup` 잘못 알아듣기 | 친구가 학생 설명을 [반례에 쓸 수 있는 범위]의 흔한 오개념 쪽으로 엉뚱하게 받아들여 되묻습니다. 학생 말과 이어지는 오개념을 먼저 고릅니다 | "그럼 싸운 군인들만 다친 거예요?" |

**질문 차례 (코드가 정함)** **[설계자 판단]**
- **질문 1**: `meaning`, `more`, `retry` 중 하나입니다. AI가 설명을 보고 고릅니다.
- **질문 2**: `mixup`입니다. 범위에 오개념이 없으면 `meaning`입니다. 지금 3단원은 모든 차시에서 오늘까지 배운 범위에 오개념이 1개 이상 있습니다.
- **질문 3**: `meaning`이나 `mixup` 중 학생의 앞 답을 따라 AI가 고릅니다. 앞에서 쓴 오개념은 다시 쓰지 않습니다.
- 질문은 최대 3개입니다. 선생님은 [바로 정리하기]로 언제든 끝낼 수 있습니다. 그래서 "2~3개"가 됩니다.
- 학생이 "몰라요"라고 해도 다음 질문으로 넘어갑니다. 다음 질문은 그 사실을 몰라도 답할 수 있는 쉬운 쪽으로 냅니다.
- 학생이 되물으면(예: "다른 나라도 왔어요?") 친구는 답을 알려 주지 않습니다. "글쎄요, 나도 궁금해요"처럼 받고 질문을 이어 갑니다. 되물음도 질문 하나를 쓴 것으로 세고, 그 질문의 표시는 `together`입니다. **[설계자 판단]**

`mixup` 질문의 조건은 다음과 같습니다.
- 오개념의 틀린 생각을 친구가 그럴듯하게 믿는 말투로 되묻습니다("그럼 ~한 거예요?", "~ 아니에요?").
- 바른 생각을 질문 안에 넣지 않습니다.
- `misconception` 칸에 그 오개념 id를 냅니다. 코드가 id가 범위 안에 있는지 검사합니다.

### 6.3 표시 (`mark`)

| 값 | 화면 글 | 언제 |
|---|---|---|
| `explained` | 잘 설명했어요 | `meaning`·`more`·`retry` 질문에 교과서 원문이나 개념과 맞는 설명을 함. 덜 자세하거나 낱말이 조금 달라도 맞는 쪽이면 여기 |
| `corrected` | 친구를 바로잡았어요 | `mixup` 질문에 친구의 틀린 생각을 받아들이지 않고, **바른 생각이나 그 까닭을 말함**. "아니에요"만 하고 까닭이 없으면 여기가 아님 |
| `together` | 함께 더 알아봐요 | 위 둘이 아님. 몰라요, 친구의 틀린 생각에 맞장구침, 원문과 어긋나는 설명, 관계없는 말 |

- 짝 검사: `mixup` 질문의 표시는 `corrected`나 `together`, 나머지 질문의 표시는 `explained`나 `together`만 됩니다(코드가 검사).
- 판단 근거는 엘렌코스처럼 [오늘 차시 교과서 원문]과 [전체 개념]만 씁니다. 맞춤법·띄어쓰기는 보지 않고, [같은 뜻으로 인정할 말]을 같은 말로 봅니다.
- 판정 하나(튼튼한 생각 등)는 쓰지 않습니다. **[결정: 질문마다 표시]**

### 6.4 친구의 말

- **반응**(`reaction`) **[설계자 판단]**: 질문 위에 붙는 친구의 짧은 한마디입니다. 학생의 앞 답을 받는 말로, 20자 이내이고 비워 둘 수 있습니다.
  - 예: "아, 그렇구나!", "괜찮아요, 나도 잘 몰라요.", "음, 헷갈려요."
  - 정답이나 학생이 하지 않은 사실을 넣지 않습니다. 학생 말을 따라 하는 것은 됩니다.
  - 칭찬이나 평가("잘했어요", "맞아요")도 하지 않습니다. 학생이 틀린 말을 해도 "맞아요"가 나오면 안 되기 때문입니다.
  - 물음표를 넣지 않습니다. 질문은 따로 있습니다.
- **질문**: 친구 말투의 존댓말입니다. 호기심 많고 조금 엉뚱한 또래가 묻는 느낌으로, 쉬운 낱말을 씁니다. 검사는 엘렌코스와 같습니다(40자, 한 문장, "요?"로 끝, 금지어 없음, 앞 질문 되풀이 금지).
- **친구의 한마디**(`thanks`, 결과): 친구가 학생 덕분에 알게 된 것을 말합니다. 40자 이내입니다.
  - **학생이 실제로 맞게 설명한 것만** 넣습니다. 학생이 깨닫지 못한 정답은 넣지 않습니다.
  - 맞게 설명한 것이 없으면 "우리 같이 더 알아봐요!"처럼 씁니다.
- **다음 시간 확인할 것**(`nextQuestion`): 오늘 주제와 관계있는 "요?"로 끝나는 질문 1개입니다. 엘렌코스 셋째 줄과 같은 검사를 씁니다. **[설계자 판단]** 결과에 남는 학생용 줄은 이 둘(한마디, 다음 시간)뿐입니다. 세 줄 정리는 쓰지 않습니다. 질문마다 표시가 "알게 된 것"과 "다시 생각한 것"의 몫을 합니다.

### 6.5 AI 호출과 응답 형식

| 호출 | 언제 | 응답(`SCHEMAS`) |
|---|---|---|
| `first` | 설명 제출 | `stage:"ask"`, `kind`(meaning/more/retry), `misconception:"none"`, `reaction:""`, `question` |
| `next` | 질문 1·2에 답함 | `stage:"ask"`, `mark`(앞 질문), `kind`(코드가 허락한 것만: 질문 2는 mixup, 질문 3은 meaning/mixup), `misconception`, `reaction`, `question` |
| `finish` | 질문 3에 답함 | `stage:"finish"`, `mark`(마지막 질문), `thanks`, `nextQuestion` |
| `finishNow` | [바로 정리하기] | `stage:"finish"`, `mark:"none"`, `thanks`, `nextQuestion` (답하지 않은 질문은 표시하지 않음) |

- 응답 형식은 호출마다 코드가 `enum`을 좁혀 만듭니다. 예를 들어 질문 2 호출의 `kind` enum은 `["mixup"]`입니다.
- 학생에게 보이는 글은 모두 이름 붙은 칸으로 받습니다(배운 것 9-3).
- 메시지 모양은 엘렌코스와 같습니다.
  - system: `[친구 프롬프트, 오늘 차시 원문(cache_control)]`. 원문이 없으면 프롬프트 글만 씁니다.
  - user: `[단원 맥락 글 T.buildContext(cache_control), 학생마다 바뀌는 글]`
  - 학생마다 바뀌는 글: `[학생의 설명]`, `[지금까지의 문답]`(질문 종류, 오개념 id, 표시 포함), `지금 할 일: …`, (다시 받을 때) 검사에 걸린 까닭.
- 프롬프트는 엘렌코스 규칙에서 판단 기준(원문·개념만 근거, 같은 뜻 말, 덜 자세한 것은 맞는 쪽, 퀴즈 금지, 정답 말하지 않기, 금지어)을 가져옵니다. 친구 역할, 질문 종류, 표시 기준을 더합니다. 예시 대화를 하나 넣습니다.

### 6.6 검사와 다시 받기

`friend.js`에 `validateFriendStep(out, expect)`를 둡니다. `guard.js`의 `checkQuestion`, `charLen`, `FORBIDDEN`을 씁니다. **[설계자 판단]** `guard.js`는 고치지 않습니다.

- **ask**
  - `kind`가 허락된 것일 것
  - `mixup`이면 `misconception`이 범위 안 id이고 앞에서 쓰지 않은 것일 것
  - `question`이 `checkQuestion`을 통과하고, 앞 질문과 같지 않을 것(띄어쓰기 무시)
  - `reaction`이 20자 이내이고, 물음표와 금지어가 없을 것. 빈 글은 괜찮음
  - `mark`(next일 때)가 앞 질문 종류와 짝이 맞을 것
- **finish**
  - `mark`가 짝이 맞을 것(`finishNow`면 "none")
  - `thanks`가 비어 있지 않고 40자 이내이며 금지어가 없을 것. "학생이" 같은 3인칭이 없을 것
  - `nextQuestion`이 엘렌코스 셋째 줄과 같은 규칙을 지킬 것(40자, "요?"로 끝)
- **걸리면** 까닭을 알려 주고 다시 받습니다. ask는 2번, finish는 3번까지입니다. 그래도 걸리면 기본값을 쓰고 `state.fallbacks`를 올립니다.
  - 질문 기본값
    - meaning/more: "조금 더 자세히 알려 줄래요?"
    - retry: "오늘 배운 것 하나만 알려 줄래요?"
    - mixup: 범위의 첫 오개념으로 만들 수 없으므로 종류를 meaning으로 바꾸고 meaning 기본값을 씁니다.
  - 반응 기본값: ""
  - 표시 기본값: `together`. 선생님이 도움말을 보게 하는 쪽이 안전합니다.
  - 끝 기본값: 한마디 "설명해 줘서 고마워요!", 다음 시간 "오늘 배운 것을 다음 시간에 다시 말해 볼까요?"
- 네트워크·키 오류는 엘렌코스와 같습니다. "AI 연결에 문제가 있어요. 선생님이 직접 물어봐 주세요." + [다시 시도]

```js
  explanation: "",          // 학생의 설명

```

### 6.8 선생님 도움말

`together` 표시가 하나라도 있으면 접힌 상자로 나옵니다. 여러 개면 질문별로 묶어 보여 줍니다.

| 어느 질문 | 들어가는 것 |
|---|---|
| `mixup` + together | 살펴볼 생각(친구의 질문), 교과서 내용(오개념의 바른 생각), 펼쳐 볼 곳(그 오개념의 교과서·차시·쪽), 바로 설명할 내용(그 오개념의 개념 문장과 쪽), 이어서 물어볼 것(반례 실마리) |
| 그 밖 + together | 살펴볼 생각(친구의 질문), 펼쳐 볼 곳(오늘 차시), 바로 설명할 내용(오늘 차시 개념 문장과 쪽) |

`ui.js`의 `teacherHelp`가 이미 하는 계산입니다. 이를 "항목 글 + 오개념 id + 오늘 차시"를 받는 작은 함수로 나눠 `ui.js`에 더하고, 두 방법이 함께 씁니다. `teacherHelp`의 이름, 인자, 결과는 그대로 둡니다(ui 테스트). 같은 오개념은 두 번 쓰지 않으므로 오개념 쪽은 겹치지 않습니다. 오개념이 아닌 질문 둘이 모두 together면 "오늘 차시" 내용(펼쳐 볼 곳, 바로 설명할 내용)은 한 번만 보이고 살펴볼 생각만 둘 다 적습니다. **[설계자 판단]**

### 7.2 실제 AI 점검 (키 필요)

`app/tests/live-friend.html` + `live-friend-cases.js`. 엘렌코스의 `live.html`을 본뜹니다.

- **가상 학생의 답은 친구 질문에 맞춰 고릅니다.** 질문이 무엇일지 미리 알 수 없기 때문입니다.

  - 그 밖은 차례대로 정한 답을 씁니다.
- 기대값: 질문마다 기대 표시(또는 "모두 together", "together 없음" 같은 느슨한 조건), 기본값 대체 0번, 퀴즈형 질문 0개, 반응 검사 통과, mixup 질문이 질문 2에 있음.
- 사례(약 15~20건, 세 교과서 고루, 3-1과 3-2)
  - 잘 설명하는 학생
  - 짧게 한 낱말만 쓴 학생
  - 오개념을 섞어 설명한 학생
  - 친구의 엉뚱한 말에 맞장구치는 학생
  - 바로잡지만 까닭 없이 "아니에요"만 하는 학생
  - "몰라요"만 하는 학생
  - 장난치는 학생
  - 되묻는 학생
  - 원문에만 있는 사실을 말하는 학생
  - 띄어쓰기 없는 답
  - 단원 마무리 차시
- 결과 표에 질문, 종류, 반응, 표시, 한마디, 대체, 호출, 시간을 보입니다. Markdown 복사도 됩니다.

- **점검 결과를 보고 어디까지 고치나** **[설계자 판단]**
  - 2장 "하면 안 되는 것"을 어기는 일은 만드는 일의 일부로 보고 프롬프트나 검사를 고쳐 다시 돌립니다. 정답을 흘리는 일, 퀴즈형 질문, 반말, 기본값 대체가 잦은 일이 그렇습니다. 고칠 때마다 이전 결과와 비교합니다(엘렌코스 9-4).
  - 표시 판단이 기대와 다른 사례(예: corrected인데 together)는 고치지 않고 정리해 사용자님께 드립니다. 고칠지는 사용자님이 정합니다.
  - 끝나는 기준: 기본값 대체 0번, 퀴즈형 질문 0개, 정답 흘림 0건. 판정 일치 건수는 기록만 합니다.
