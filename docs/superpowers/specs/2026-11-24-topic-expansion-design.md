# 주제 확장 설계: 6·25 하나에서 5학년 2학기 사회 전체로

2026-11-24 · 앞선 설계: `docs/superpowers/specs/2026-11-24-elenchus-mvp-design.md`

대화에서 사용자님이 정한 것은 **[결정]**, 설계자가 정한 것은 **[설계자 판단]**으로 표시했습니다.

## 1. 의도와 이유

- 지금 엘렌코스 앱은 6·25 전쟁 한 주제만 쓸 수 있습니다. 이것을 5학년 2학기 사회 전체(세 단원)로 넓혀서, 어느 사회 수업이 끝나든 바로 정리활동에 쓸 수 있게 합니다.
- 교사는 진도표대로 **오늘 차시**를 고릅니다. AI는 다음 두 가지를 구분합니다.
  - 학생 말이 맞는지 판단할 때: 그 차시가 속한 **단원 전체**를 봅니다. 그래서 지난 차시 내용을 말해도 "범위 밖"이 되지 않습니다. 앞 소단원 내용도 마찬가지입니다.
  - 반례를 고를 때: **오늘 차시** 내용을 먼저 쓰고, 그다음 **이미 배운 차시** 내용을 씁니다. 아직 배우지 않은 차시 내용은 쓰지 않습니다. **[결정: 섞는 방식]**
- 차시 하나만 범위로 쓰지 않는 까닭은 두 가지입니다.
  - 5학년 학생은 "오늘 배운 것"에 지난 시간 내용을 자주 섞습니다. 맞는 말인데도 "다시 말해 볼까요?"라는 말을 들으면 학생은 틀렸다고 느낍니다.
  - 내용이 1~2쪽뿐인 짧은 차시는 반례와 오개념 재료가 모자랍니다. 억지로 채우면 교과서 근거가 없는 오개념이 섞입니다. 6·25 때 m06 실마리가 이 문제로 판정을 흔들었습니다.

## 2. 목표 · 비목표 · 하면 안 되는 것

**목표**
1. 시작 화면에서 교과서 → 단원 → 차시 순서로 고르면, 앱이 알아서 그 차시의 주제 묶음과 반례 범위를 정합니다.
2. 세 교과서(천재·아이스크림·비상)의 내용 차시와 단원 마무리 차시를 모두 고를 수 있습니다.
3. 개념과 오개념은 앞선 설계와 같은 원칙을 따릅니다.
   - 교과서 내용만 담고, 문장을 그대로 옮기지 않고 요약합니다.
   - 쪽 번호와 차시가 출처로 붙습니다.
   - 설계자가 교과서 원문과 대조해 검증한 뒤 `reviewed: true`로 둡니다. 선생님이 항목을 하나하나 검토하지 않아도 되게 합니다. **[결정: 검증은 설계자가 맡음]**
4. 이미 검증한 6·25 데이터와 지금 동작(판정 규칙, 선생님 도움말, 인쇄)은 그대로 유지됩니다.

**작업 순서 [결정]**
- 단원 하나를 끝까지 마치고 main에 합친 뒤 다음 단원으로 넘어갑니다.
  - "끝까지"는 데이터 → 검증 → 실제 AI 점검까지입니다.
- 순서는 **3단원 → 1단원 → 2단원**입니다.
- 이 설계의 첫 구현 계획은 아래 두 가지를 다룹니다.
  - 공통 틀 변경(차시 선택, 묶음·차시 범위, 프롬프트 일반화)
  - **3단원** 데이터
- 1·2단원은 같은 공정을 되풀이하는 다음 계획으로 만듭니다.

**비목표**
- 다른 학년·학기·과목
- 단원 도입, 창의 융합, 생각을 펼쳐요, 교실 놀이처럼 활동만 있는 차시
- 나머지 소크라테스식 방법 5가지
- 지난번에 미뤄 둔 작은 문제 10개(이번 작업과 따로 다룹니다)

**하면 안 되는 것** (기능이 돌아가도 이렇게 되면 실패입니다)
- 지난 차시의 맞는 내용을 AI가 "범위 밖"이나 "다시 생각해 볼 것"으로 보는 것
- 교과서에 근거가 없는 오개념이나 반례 실마리가 데이터에 들어가는 것
- 오늘 차시와 동떨어진 차시 내용으로 반례를 던지는 것
  - 같은 묶음 안이라도, 오늘 차시에 쓸 오개념이 있는데 다른 차시 것을 고르는 경우를 말합니다.
- 6·25에서 검증된 판정 품질(실제 점검 9/10)이 떨어지는 것
- 교과서 원문(추출 텍스트·그림)이 저장소에 커밋되는 것

## 3. 제약

- 앞선 설계의 제약을 모두 따릅니다.
  - 빌드 없는 정적 앱이고 `app/index.html`을 file://로 엽니다.
  - API 키는 선생님이 [설정]에 직접 넣습니다.
  - 학생 이름은 모으지 않습니다.
  - 모델은 Haiku 5.5, effort low입니다.
  - 질문 40자 이내, 금지어, 세 줄 정리 형식을 지킵니다.
- **file://에서는 fetch를 쓸 수 없습니다.** 그래서 데이터 파일은 지금처럼 `<script>`로 불러오고 `window.SOKRATES_TOPICS[id]`에 등록합니다.
- **저장소는 비공개입니다.** 교과서에서 뽑은 텍스트(`work/`)와 교과서 폴더는 커밋하지 않습니다.
- **교과서 원본**은 `C:\Users\User\Desktop\claude2\classall\textbook\{천재_5-2,아이스크림_5-2,비상_5-2}\차시\*.pdf`에 있습니다.
  - 파일 이름은 `{단원}단원_{차시:02d}차시_{학습내용}.pdf`입니다.
  - 2차시 이상 이어지는 수업은 첫 차시 번호로 파일이 하나만 있습니다(예: 천재 3단원 8·9차시 → `08차시` 파일 하나).
  - 쪽 범위와 차시 번호는 각 폴더의 진도표 xlsx에 있습니다.
- **텍스트 레이어:** 세 교과서 모두 차시 파일에서 글자를 읽을 수 있습니다(2026-11-24 점검, 한글 비율 63~66%).
  - 6·25 작업 때 비상 교과서 일부 쪽은 글자가 깨져서 그림으로 읽었습니다.
  - 그러니 쪽마다 글자가 제대로 나오는지 확인하고, 깨진 쪽만 그림으로 바꿔 읽습니다.
- **비용:** 호출 한 번에 묶음 전체 개념이 들어가도 입력은 5천~8천 토큰 정도입니다. Haiku 5.5 가격으로 호출당 1원 안팎이라 문제가 되지 않습니다.

## 4. 만드는 방법: 고려한 방안

| 방안 | 내용 | 득실 | 결과 |
|---|---|---|---|
| 공통 묶음만 | 6·25처럼 세 교과서 공통 내용을 한 주제로 | 작업이 가장 적음. 하지만 교사가 진도표 차시로 고를 수 없고, 반례가 오늘 수업에 맞춰지지 않음 | 채택 안 함 |
| 차시마다 하나 | 차시가 곧 주제 | 범위가 가장 정확함. 하지만 지난 차시 내용을 범위 밖으로 보고, 짧은 차시는 오개념이 모자람 | 채택 안 함 |
| 단원 하나가 주제 | 3개 주제 | AI가 볼 내용이 너무 많아 질문이 흐려짐 | 채택 안 함 |
| **섞는 방식** | 차시로 고르고, 판단은 묶음, 반례는 오늘 차시 먼저 | 위 두 방안의 장점을 모두 얻음. 앱이 판단 범위와 반례 범위를 이미 나눠 다루고 있어 구조 변경이 작음 | **[결정] 채택** |

만드는 순서는 두 가지를 놓고 정했습니다.
- 단원별로 하나씩 끝내기: **[결정] 채택**
- 전부 한 번에: 중간에 쓸 것이 없고, 공정에 실수가 있으면 전체를 다시 고쳐야 해서 뺐습니다.

## 5. 설계

### 5.1 주제 묶음 = 교과서의 소단원 **[설계자 판단]**

세 교과서 진도표를 보면 소단원(주제)이 같습니다. 국가 교육과정이 같기 때문입니다. 그래서 묶음은 따로 만들지 않고 **교과서 소단원**을 그대로 씁니다.
- 대화에서는 "약 14개 묶음"이라고 말씀드렸습니다.
- 소단원 단위로 하면 묶음 수가 7~8개로 줄고, 묶음 하나가 3~6차시를 덮습니다.
- 묶음은 데이터 파일을 나누는 단위이고, 오개념 개수 규칙을 확인하는 단위입니다.
- 실제 판단 범위와 반례 범위는 5.3처럼 단원과 차시 순서로 정합니다.

3단원은 묶음 둘입니다(차시 번호는 진도표 기준, 괄호 안은 파일 번호).

| 묶음 | 천재 | 아이스크림 | 비상 |
|---|---|---|---|
| 3-1 일제의 식민 통치와 저항 | 2, 3, 4, 5, 6, 7 | 2, 3, 4, 5, 6~7(06) | 2, 3~4(03), 5, 6~7(06) |
| 3-2 8·15 광복과 6·25 전쟁 | 8~9(08), 10, 11, 12 | 8~9(08), 10~11(10), 12 | 8~9(08), 10, 11~12(11) |
| 단원 마무리 | 14 | 14(생각 그물, 13 생각을 펼쳐요는 뺌) | 13 |

- 세 진도표(2026-11-24 확인)의 쪽수와 차시 번호로 만든 표입니다.
- 소단원 이름은 출판사마다 조금씩 다릅니다. 예를 들어 아이스크림은 "식민 통치와 저항으로 달라진 사회와 생활 모습"입니다. 하지만 다루는 내용이 같아서 묶음 제목은 하나로 씁니다.
- 기존 6·25 주제(`id "625"`)는 **3-2 묶음 안으로 들어갑니다.**
  - 개념 c01~c25와 오개념 m01~m10의 내용, 쪽 번호, 힌트는 그대로 둡니다.
  - 광복·정부 수립 개념과 오개념을 더합니다.

### 5.2 데이터 형식

묶음 하나 = 파일 하나: `app/data/topic-{단원}-{소단원}.js`(예: `topic-3-1.js`). 지금 형식에서 바뀌는 점만 적습니다.

```js
{
  id: "3-1", unit: 3, title: "일제의 식민 통치와 저항",
  unitTitle: "식민 통치와 저항, 전쟁이 바꾼 사회와 생활",
  grade: "5-2", subject: "사회",
  textbooks: [
    { id: "chunjae", name: "천재교과서",
      lessons: [ { id: "3-2", title: "나라를 지키기 위한 사람들의 노력 알아보기", pages: "122~125" }, ... ] },
    ...
  ],
  concepts:       [ { id: "3-1.c01", text, sources: { chunjae: { lesson: "3-2", page: "123" }, ... } } ],
  misconceptions: [ { id: "3-1.m01", wrong, truth, counterHints, concepts, sources, reviewed } ],
  synonyms: [ [...], ... ]
}
```

- **`lessons`는 문자열 배열에서 객체 배열로 바뀝니다.**
  - `id`는 진도표의 시작 차시 번호입니다. 2차시짜리는 첫 번호를 쓰고 제목에 "(8~9차시)"를 붙입니다.
  - `title`은 진도표의 학습내용입니다.
  - `pages`는 진도표의 쪽수입니다.
- **id 앞에 묶음 id를 붙입니다.** 여러 묶음을 한 화면에서 쓸 때 id가 겹치지 않게 하려는 것입니다.
  - 6·25 항목은 `3-2.c01`~`3-2.c25`, `3-2.m01`~`3-2.m10`이 됩니다.
  - 새 광복·정부 수립 항목은 그 뒤 번호를 이어서 씁니다.
- 출처의 `lesson`은 `lessons[].id` 중 하나여야 합니다. `validateTopic`이 이것을 검사합니다.
- **단원 정보:** `app/data/units.js`에 단원 번호, 단원 이름, 교과서별 단원 마무리 차시를 둡니다. 시작 화면은 이 파일로 목록을 만듭니다.
- **`validateTopic`의 오개념 개수 규칙:** "교과서마다 2개 이상"을 지금처럼 **묶음 단위**로 확인합니다. 차시 단위로는 요구하지 않습니다.

### 5.3 범위 계산

`buildContext(unitTopic, textbookId, lessonId)`로 바뀝니다.

- `unitTopic`은 그 단원의 모든 묶음을 `mergeTopics(topics)`로 합친 것입니다.
  - id에 묶음 이름이 붙어 있어서 그냥 이어 붙이면 됩니다.
  - `lessons`는 교과서마다 진도표 순서대로 이어 붙입니다.
- `[전체 개념]`: 단원의 개념 전부입니다. 학생 말이 맞는지 판단하는 데 씁니다.
  - 아직 배우지 않은 차시 개념도 넣습니다. 판단에는 해가 없고, 학생이 미리 아는 내용을 "범위 밖"으로 보지 않게 해 줍니다.
  - 3단원 전체가 개념 60~80개 정도라 호출당 비용은 그대로 1원 안팎입니다.
- `[오늘 차시: {교과서} {단원}단원 {차시}차시 {제목}]`: 오늘 차시 개념의 id 목록입니다.
- `[반례에 쓸 수 있는 범위]`: 그 교과서 출처가 있는 개념과 오개념 가운데 **오늘 차시와 이미 배운 차시**의 것만 씁니다.
  - "이미 배운 차시"는 그 교과서의 진도표 순서로 판단합니다. 앞 소단원도 포함합니다.
  - 오늘 차시 오개념을 먼저 쓰고, 이미 배운 차시 오개념은 "앞 차시"라고 표시해 뒤에 붙입니다.
  - 오늘 차시 오개념이 0개면 이미 배운 차시 전체를 같은 순위로 둡니다.
  - 주제 마무리만 하는 차시가 대표적인 예입니다. 마무리 차시에 자기 내용이 있으면(예: 천재 12차시 6·25 피해) 그것이 먼저 옵니다.
  - 아직 배우지 않은 차시의 오개념은 넣지 않습니다.
- `[같은 뜻으로 인정할 말]`: 단원 전체의 것을 씁니다.
- **단원 마무리 차시를 고르면** 단원 전체가 같은 순위의 반례 범위입니다. "오늘 차시" 줄은 없습니다.

`lessonId`를 주지 않으면 지금처럼 주어진 데이터 전체를 같은 순위로 다룹니다. 기존 테스트가 이 경로로 돌아갑니다.

앞 단원 내용(예: 3단원 수업 뒤 조선 이야기)은 범위 밖으로 봅니다. 드문 일이고, 범위가 단원을 넘으면 AI가 볼 내용이 너무 많아집니다. **[설계자 판단]**

### 5.4 프롬프트

`methods/elenchus.js`의 `SYSTEM_PROMPT`에서 6·25에 묶인 표현을 일반화합니다.
- "6·25와 관계없는" → "오늘 주제와 관계없는"(규칙 6, target 우선순위 2, hold 정의)
- target 우선순위 1)에 한 줄을 더합니다: 오개념이 의심되는 항목이 여럿이면 **오늘 차시 항목**을 고릅니다.
- 규칙 1에 한 줄을 더합니다: 반례는 오늘 차시 오개념에서 먼저 고르고, 앞 차시 오개념은 학생이 그 내용을 말했을 때만 씁니다.
- 예시(6·25 천재)는 그대로 둡니다. 형식을 보여 주는 예시입니다.
  - 다만 예시 속 오개념 id `"m01"`은 새 형식 `"3-2.m01"`로 바꿉니다.

### 5.6 데이터 만들기와 검증 공정 (단원마다 되풀이)

1. **추출:** `tools/extract_625.py`를 일반화한 `tools/extract_lessons.py`로 차시 파일 텍스트를 `work/{단원}/{교과서}/{차시}.txt`에 뽑습니다. 이 폴더는 커밋하지 않습니다.
   - 글자가 깨진 쪽은 PNG로 그려 눈으로 읽습니다.
   - 쪽 번호는 인쇄된 쪽을 씁니다.
2. **초안:** 묶음마다 개념(차시당 4~8개)과 오개념(묶음·교과서당 최소 2개, 차시당 0~2개)을 씁니다.
   - 오개념은 5학년이 실제로 흔히 하는 착각이어야 합니다.
   - 반례 실마리는 교과서 문장에서 바로 찾을 수 있어야 합니다.
3. **검증:** 새 맥락의 검토자 에이전트가 항목마다 교과서 텍스트와 대조합니다. 개념 내용, 출처 차시, 쪽, 실마리 근거, 같은 뜻 말을 봅니다.
   - 6·25 때와 같은 방식입니다.
   - 고친 내용은 커밋 메시지에 남깁니다.
4. **실제 AI 점검:** `tests/live-cases.js`에 단원마다 사례를 더합니다. 사례마다 `topicId`와 `lessonId`가 붙습니다. **[설계자 판단]**
   - **기존 6·25 사례 10개**는 회귀 점검으로 그대로 둡니다. 각 교과서의 6·25 차시를 `lessonId`로 붙입니다.
   - **새 사례 12개:** 교과서마다 4개씩입니다.
     - 3-1 차시 "하나 틀림" 1개
     - 3-1 차시 "모두 맞음" 1개
     - "지난 차시 섞음" 1개: 3-2 첫 차시에서 3-1 내용을 섞은 경우로, 소단원 경계를 일부러 넘깁니다.
     - 단원 마무리 "하나 틀림" 1개
   - 선생님이 `live.html`을 실제 키로 돌립니다. 22건이고 비용은 수십 원입니다.
   - **통과 기준:**
     - 6·25 사례 10개 중 9개 이상, 새 사례 12개 중 11개 이상이 기대 판정
     - "지난 차시 섞음" 사례 3개는 모두 섞은 항목이 `ok`
   - 기준에 못 미치면 프롬프트나 데이터를 고쳐 다시 돌립니다. 통과하기 전에는 main에 합치지 않습니다.
5. 다 통과하면 main에 합칩니다.

### 5.7 테스트

- 지금 테스트 89개가 계속 통과해야 합니다. 6·25 데이터 테스트는 새 id(`3-2.*`)와 새 `lessons` 형식에 맞춰 고칩니다.
- 새 테스트:
  - `validateTopic`: 출처 차시가 `lessons`에 없는 경우를 잡는지

    - 앞 소단원의 이미 배운 차시가 들어가는지
    - 오늘 차시 오개념이 0개일 때 이미 배운 차시 전체로 넘어가는지
  - `mergeTopics`와 단원 마무리 범위
  - 시작 화면: 교과서 → 단원 → 차시를 고르면 세션이 올바른 `topic`·`lessonId`로 만들어지는지
  - 모든 데이터 파일 검사: `validateTopic` 오류 0, 모든 오개념 `reviewed: true`
