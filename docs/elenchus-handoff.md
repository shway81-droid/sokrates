## 0. 왜 만드는가 (사용자님 말씀)

- **출발**: 정재승 교수가 AI 시대의 평가로 소크라테스 대화법("소크라테스트")을 쓴다는 이야기에서 시작했습니다.
- **풀고 싶은 문제**: 수업이 끝나면 "학생들이 오늘 배운 것을 정말 이해했을까?"가 늘 궁금합니다. 하지만 매 수업마다 평가로 확인하기는 어렵습니다.
- **방법**: 수업 말미에 소크라테스식으로 확인합니다. 원래는 소크라테스만큼 아는 사람이 학생 수만큼 있어야 하지만, 그 역할을 AI가 맡습니다.
- **여섯 방법은 같은 맥락입니다.** 엘렌코스가 MVP이고, 나머지 다섯 방법도 같은 목적과 원칙으로 만듭니다.
- **엘렌코스의 핵심**: AI가 답을 주지 않고, 반례로 학생이 모르는 것을 **스스로 꺼내 알게** 합니다. 그래서 퀴즈식 질문과 선다형 보기는 쓰지 않습니다.

## 사용자님이 정한 것 (바꾸려면 다시 여쭐 것)

| 정한 것 | 내용 |
|---|---|
| 교과서 | 세 교과서를 하나로 합치고, 시작할 때 교과서를 고름. 자료는 세 교과서 내용으로만 한정 |
| 폴더 | 공통 틀(`core/`)과 방법별 파일(`methods/`)을 나눔 |
| 범위 | 처음에는 6·25 전체 → 넓힐 때 "오늘 차시 + 이미 배운 차시"를 섞는 방식, 3단원부터 |
| 데이터 검토 | 개념·오개념 검토는 사용자님께 넘기지 않고 AI(새 맥락의 검증 에이전트)가 원문과 대조해 함. 사용자님께 보일 때는 JSON이 아니라 웹 화면으로 |
| 3-2.m01 | "1953년에 끝났다" 오개념은 그대로 둠 |
| "몰라요"만 한 학생 | 판정 보류 |
| 이유 묻기 | 최대 2번 |

| 교과서 밖 판단 문제 | 교과서와 조금만 달라도 "교과서 밖"으로 보던 문제(천재 130쪽 "죽거나 다쳤다" 사례) → 차시 원문을 함께 주고 `unsure`를 더함 |
| 반례 질문 | 사실 퀴즈 → 학생 말을 따라가는 엘렌코스식 질문 |
| 선다형 | 검토했다가 쓰지 않기로 함. 다시 꺼내지 않음 |
| 모델 | 하이쿠 → 소넷 → 다시 하이쿠(지금 기본값) |

## 사용자님과 일하는 방식

- **테스트 예시**: 차시를 정해 "배운 3가지" 예시를 5명분 보여 드립니다. 학습 수준이 낮은 학생, "몰라요"·고집·되묻기 같은 실제 답도 넣습니다. 사용자님이 화면에서 직접 해 보십니다.
- **보완 판단은 사용자님이 합니다.** 테스트를 돌린 뒤 보완할 점을 정리해 말씀드리고, 고칠지는 사용자님이 정합니다.
- **API 키는 사용자님이 [설정]에 직접 넣습니다.** 채팅에 붙여 넣게 하지 않습니다.
- 커밋·푸시는 말씀하실 때만 합니다. "커밋"이라고 하시면 보통 푸시까지 바라십니다.
- 질문과 보고는 한국어 존댓말로, 쉬운 말로 합니다.

## 1. 한눈에

| 항목 | 지금 상태 |
|---|---|
| 대상 | 초등 5학년 2학기 사회. 세 교과서(천재·아이스크림·비상) |
| 범위 | 3단원(3-1 일제의 식민 통치와 저항, 3-2 8·15 광복과 6·25 전쟁). 1·2단원은 아직 없음 |
| 쓰는 곳 | 교사 PC의 크롬, 교실 TV. 학생 1명씩, 5~7분 |
| 실행 | 서버 없이 `app/index.html`. 개발 중에는 `python -m http.server 8765 --directory app` (`.claude/launch.json`의 `sokrates-app`) |
| AI | Claude API를 브라우저에서 직접 호출. 키는 선생님이 [설정]에 넣고 그 PC의 localStorage에만 저장 |
| 기본 모델 | `claude-haiku-5-5`, 생각하는 정도 `low`. 설정에서 소넷·오퍼스로 바꿀 수 있음 |
| 테스트 | `cd app && node --test "tests/*.test.js"` → 177개 통과 |
| 실제 점검 | `app/tests/live.html` (가상 학생 28명). 최근 결과: 소넷 26/28, 하이쿠 25/28 |
| 저장소 | 비공개 GitHub `shway81-droid/sokrates`, 브랜치 `main` |

**지켜야 할 것 (모든 방법에 공통)**
- AI가 정답이나 설명을 말하지 않습니다. "틀렸", "정답은", "오답" 같은 말을 쓰지 않습니다.
- 학생이 잘못했다는 느낌을 주는 말을 쓰지 않습니다. 예를 들어 "허점을 찾았어요" 대신 "모르는 것을 알게 되었어요"라고 씁니다. 질문은 "~요?"로 끝나는 존댓말입니다.
- 화면에 빨간색, X 표시, 점수를 쓰지 않습니다.
- 반례와 판단은 **고른 교과서의 내용 안에서만** 합니다. AI가 따로 아는 지식은 쓰지 않습니다.
- 학생 이름은 받지 않습니다. 대화는 메모리에만 있고 [다음 학생]을 누르면 사라집니다.
- 교과서 원문(`work/`, `app/local/`)은 출판사 저작물이라 커밋하지 않습니다. 데이터에는 교과서 문장을 25자 이상 그대로 옮기지 않습니다(테스트로 검사).
- API 키는 코드나 채팅에 넣지 않습니다.

## 2. 엘렌코스가 하는 일

학생이 "오늘 배운 3가지"를 말하면, AI가 그중 흔들리는 생각 **1개**에 반례 질문을 던집니다. 학생은 질문에 답하며 자기 말이 앞뒤가 안 맞는다는 것을 **스스로** 알아차립니다.

### 화면 흐름

1. **설정**(처음 한 번): API 키, 모델, 생각하는 정도
2. **시작**: 정리 방법 · 교과서 · 단원 · 오늘 차시. 마지막으로 고른 값을 기억합니다.
3. **배운 3가지**: 맨 위에 학습문제(차시 제목), 입력 칸 3개
4. **확인과 문답**: 항목마다 확인 표시, 질문 카드 1장, 진행 점(●○○), [바로 정리하기]
5. **결과**: 판정 1개, 세 줄 정리, (보류·다시 볼 생각이면) 접힌 선생님 도움말, 문답 기록, [복사] [인쇄] [다음 학생]

오른쪽 위에 지난 시간(예: 4:12)이 나옵니다.

### 확인 표시 (checks)

| 값 | 화면 글 | 뜻 |
|---|---|---|
| `ok` | ✓ | 교과서 원문이나 개념과 맞음 |
| `think` | 더 생각해 볼 것 | 학생 문장 안에 오개념의 틀린 주장이 실제로 있음 |
| `unsure` | 교과서에서 함께 찾아봐요 | 주제와 관계있지만 교과서에서 확인되지 않고, 어긋나지도 않음 |
| `outside` | 오늘 주제와 다른 이야기예요 | 장난, 빈말, "모르겠다" |

### 묻는 방식 (mode)과 질문 수

| mode | 언제 | 최대 질문 |
|---|---|---|
| `counter` 반례로 묻기 | `think` 항목이 있을 때 | 3번 |
| `retry` 다시 말해 보게 하기 | `think`는 없고 `outside`가 있을 때 | 3번 |
| `reason` 이유 묻기 | 모두 `ok`나 `unsure`일 때. 교과서에 까닭이 나오는 항목만 | 2번 |

### 판정 (verdict)

| 값 | 라벨 | 언제 |
|---|---|---|
| `strong` | 튼튼한 생각 | 반례에도 근거를 대며 지켰거나, 이유를 근거 있게 설명함 |
| `revisit` | 다시 볼 생각 | 학생이 모르던 것을 스스로 알아차리거나 고쳐 말함. "제 말이 맞는지 모르겠어요"도 포함 |
| `hold` | 판정 보류 | 어느 쪽도 아님. 근거 없이 끝까지 고집해도 보류 |

`revisit`이면 결과에 "처음 생각 → 고친 생각"이 함께 나옵니다. 이유 묻기로 `strong`이 되면 문구가 "까닭을 스스로 설명했어요"로 바뀝니다.

### 세 줄 정리

알게 된 것 / 다시 생각한 것 / 다음 시간 확인할 것(질문). 각 줄은 30자 안팎이고 40자를 넘으면 안 됩니다. 학생이 하지 않은 말, 특히 깨닫지 못한 정답은 적지 않습니다.

### 선생님 도움말

판정 보류나 다시 볼 생각일 때만 접힌 상자로 나옵니다. TV에서 학생에게 답이 바로 보이지 않게 하려는 것입니다. 선생님이 수업 마무리에서 교과서를 다시 펴지 않고 바로 설명할 수 있게 하는 것이 목적입니다. 들어 있는 것은 다음과 같습니다.
- 살펴볼 생각
- 교과서 내용(오개념의 바른 생각)
- 펼쳐 볼 곳(교과서·차시·쪽)
- 바로 설명할 내용(검증한 개념 문장과 쪽)
- 이어서 물어볼 것(반례 실마리)

### 반례 질문을 만드는 방식 (2026-11-24에 바꿈)

처음에는 반례가 "1953년에 맺은 협정의 이름은?" 같은 **사실 퀴즈**였습니다. 그 사실을 모르는 학생은 "몰라요"에서 막혔습니다. 지금은 학생 말을 따라가 모순을 보게 합니다.
- 첫 질문은 학생 말이 맞다면 어떻게 되는지 묻습니다. 또는 상식으로 답할 수 있는 것을 묻습니다.
  - 예: "다친 사람은 군인뿐" → "전쟁이 난 곳에는 군인만 살고 있었을까요?"
- 다음 질문은 학생이 인정한 말을 처음 한 말과 나란히 놓습니다.
- 학생이 까닭을 대면 그 까닭을 시험합니다. 예: "싸우지 않은 사람은 전쟁에서 다치지 않을까요?"
- "모르겠어요"라고 하면 그 사실을 몰라도 답할 수 있는 더 쉬운 질문으로 바꿉니다.
- 학생이 되물으면 판정하지 않고 질문을 이어 갑니다. 답은 알려 주지 않습니다.
- **반례를 만들 수 있다고 해서 `think`로 정하지 않습니다.** 이 문장이 없으면 맞는 말까지 오개념으로 보는 퇴보가 생깁니다(9장 참고).

선다형 반례도 검토했지만 쓰지 않기로 했습니다(사용자님 결정).

## 3. 폴더와 역할

```
app/
  index.html          교사 화면. 스크립트 순서: 데이터 → 공통 부품 → 방법 → 화면 제어
  review.html         오개념 검토 페이지(묶음별, 검토 표시는 localStorage)
  core/
    llm.js            Claude 호출, 설정 저장. 서버로 옮길 때 createClaudeLLM만 바꿈
    guard.js          AI 출력 검사(질문·확인·판정·세 줄 정리)
    topic.js          데이터 검사, 묶음 합치기, 범위 거르기, 프롬프트용 맥락 만들기
    catalog.js        시작 화면 선택 계산(교과서 → 단원 → 차시), 원문 꺼내기
    ui.js             판정 문구, 확인 표시 글, 결과 글, 선생님 도움말 계산, el() 도우미
    app.js            화면 제어(설정·시작·입력·문답·결과), 방법 등록
    style.css
  data/
    units.js          단원 목록, 단원 마무리 차시
    topic-3-1.js      3-1 묶음(개념·오개념·같은 뜻 말)
    topic-3-2.js      3-2 묶음
  methods/
    elenchus.js       엘렌코스: 시스템 프롬프트, 응답 형식, 세션(문답 흐름)
  local/texts.js      교과서 원문(선생님 PC에만, git 제외)
  tests/              단위 테스트, 실제 점검 페이지와 사례
tools/
  extract_lessons.py  차시 PDF → work/{단원}/{교과서}/{차시}.txt
  build_local_texts.py work/ → app/local/texts.js
```

모든 JS 파일은 `(function (root) { … })(this)` 모양의 일반 스크립트입니다. 브라우저에서는 `window.Sok…`로, Node 테스트에서는 `module.exports`로 씁니다. 빌드 과정이 없습니다.

### 다음 방법이 그대로 쓸 수 있는 것

| 부품 | 다시 쓰는 방법 |
|---|---|
| `llm.js` | 그대로. `llm.call({ system, messages, schema })` → JSON 객체 |
| `topic.js`, `catalog.js` | 그대로. 단원·차시 선택, 오늘까지 배운 범위, 단원 맥락 글 |
| 데이터(`data/`) | 개념·오개념·같은 뜻 말을 그대로. 방법에 따라 칸을 더할 수 있음 |
| 원문(`local/texts.js`) | 그대로. `Cat.sourceText(texts, 교과서, 차시)` |
| `guard.js` | 질문 검사(`checkQuestion`: 40자, 한 문장, "요?"로 끝, 금지어)는 그대로. 판정·정리 검사는 엘렌코스용 |
| 캐시 구조 | 그대로 따라 하기(6장) |
| 점검 페이지 방식 | `live.html` + `live-cases.js`를 본떠 방법마다 만들기 |

### 다음 방법을 위해 손봐야 하는 것

**화면이 엘렌코스 모양에 묶여 있습니다.** 이것이 가장 큰 준비 거리입니다.
- `app.js`의 `registerMethod`는 `{ id, name, createSession }`만 받습니다.
- 그런데 `input`·`talk`·`result` 화면이 엘렌코스 세션의 상태 모양을 그대로 가정합니다. 배운 3가지, `checks`, `target`, `turns`, `verdict`, `summary`가 그렇습니다.
- 시작 화면의 "반례 질문은 …" 안내, 판정 문구, 선생님 도움말도 엘렌코스용입니다.

다음 방법을 붙이기 전에 둘 중 하나를 정해야 합니다.
1. **방법마다 자기 화면을 가져오기**: `registerMethod({ id, name, createSession, views })`. 공통 화면(설정·시작)만 `app.js`에 남깁니다.
2. **공통 세션 모양을 정하기**: 모든 방법이 같은 상태 모양(입력 → 질문/답 반복 → 결과)을 따르게 합니다.

방법 다섯 가지의 입력과 결과가 서로 많이 다릅니다. 왜 사다리는 사다리 그림, 오답 탐정은 틀린 곳 찾기, 문제 출제자는 문제 고치기를 남깁니다. 그래서 1번이 맞을 것으로 봅니다. 다음 방법의 설계 때 정합니다.

그 밖에 엘렌코스 전용인 것도 있습니다.
- `ui.js`의 `VERDICT_TEXT`, `CHECK_TEXT`, `SUMMARY_LABELS`, `rethink`, `teacherHelp`, `resultText`
- `guard.js`의 `validateStep`(stage·checks·mode 짝 검사), `checkSummary`

## 4. 데이터

### 단원 · 묶음 · 차시

- **단원**(`units.js`): 시작 화면의 단원 목록입니다. 단원마다 묶음 목록(진도표 순서)과 교과서별 단원 마무리 차시가 있습니다.
- **묶음**(`topic-{단원}-{소단원}.js`): 교과서의 소단원입니다. id에 묶음 이름이 붙습니다(예: `3-2.m01`).
- **차시**: 교과서마다 `{ id, no, title, pages }`. `id`는 진도표 시작 차시(예: `"3-10"`), `no`는 화면 번호(예: `"10~11"`)입니다.

### 묶음의 칸

```js
{
  id: "3-2", unit: 3, title: "8·15 광복과 6·25 전쟁", grade: "5-2", subject: "사회",
  textbooks: [{ id: "chunjae", name: "천재교과서", lessons: [{ id, no, title, pages }, …] }, …],
  concepts: [{ id: "3-2.c01", text: "요약 문장", sources: { chunjae: { lesson: "3-11", page: "150" }, … } }],
  misconceptions: [{
    id: "3-2.m06", wrong: "틀린 생각", truth: "바른 생각",
    counterHints: ["반례 질문 예 1?", "반례 질문 예 2?"],   // 학생 말을 따라가는 질문 꼴, 40자 이내, 2개 이상
    concepts: ["3-2.c19"], sources: { … }, reviewed: true,
  }],
  synonyms: [["국제 연합군", "유엔군", "UN군"], …],
}
```

- 개념은 교과서 문장을 그대로 옮기지 않고 요약합니다. 쪽은 인쇄된 쪽입니다.
- 오개념은 교과서마다 2개 이상 있어야 합니다(`validateTopic`).
- 3단원에는 개념이 많고, 오개념은 39개입니다(3-1에 21개, 3-2에 18개. 2026-11-25 오답 탐정 차시를 채우려고 4개, 이어 7개 더함). 모두 `reviewed: true`입니다.

### 범위 계산 (`buildContext`)

AI에게 주는 맥락 글은 네 부분입니다.
- `[전체 개념]`: 단원 전체입니다. 맞는지 판단할 때 씁니다.
- `[오늘 차시]`: 오늘 차시의 개념 id입니다.
- `[반례에 쓸 수 있는 범위]`: 고른 교과서에서 **오늘까지 배운 차시**만 넣습니다. 오늘 차시 오개념이 먼저 옵니다.
- `[같은 뜻으로 인정할 말]`

단원 마무리를 고르면 단원 전체가 범위입니다.

### 데이터 만들기 공정 (단원마다 되풀이)

1. `tools/extract_lessons.py`로 차시 글을 뽑습니다(`work/`, 커밋 안 함).
2. 초안 에이전트가 개념(차시당 4~8개)과 오개념을 씁니다.
3. **새 맥락의 검증 에이전트**가 항목마다 원문과 대조합니다. 내용, 출처 차시, 쪽, 실마리 근거, 같은 뜻 말을 봅니다.
4. 실제 AI 점검 사례를 더해 돌립니다. 통과해야 main에 합칩니다.
5. `tools/build_local_texts.py`로 원문 파일을 만듭니다(선생님 PC).

## 5. 문답 흐름과 검사 (`methods/elenchus.js`)

**원칙: 몇 번 물을지, 언제 끝낼지, 검사에 걸리면 어떻게 할지는 코드가 정합니다. AI는 정해진 JSON 하나만 돌려줍니다.**

| 호출 | 언제 | 응답 형식(`SCHEMAS`) |
|---|---|---|
| 확인 | 배운 3가지 제출 | `check`: checks, target, mode, misconception, question |
| 다음 | 학생 답(질문이 남았을 때) | `next`: stage question 또는 verdict |
| 판정 | 마지막 답, [바로 정리하기] | `verdict`: verdict, summary |
| 질문만 다시 | 질문이 검사에 걸렸을 때 | `question`: stage는 question만 |

- 세 줄 정리는 칸 이름(`learned`, `rethought`, `nextQuestion`)으로 받아 앱 안에서 배열로 바꿉니다. 배열로만 받으면 AI가 학생의 3가지를 그대로 옮겨 적는 일이 잦았습니다.
- `misconception`은 범위 안의 id일 때만 받아들입니다(선생님 도움말에 씀).
- [다음 학생]을 누르면 세대 번호를 올려 늦게 온 응답을 버립니다.
- 네트워크·키 오류면 "AI 연결에 문제가 있어요. 선생님이 직접 물어봐 주세요."를 띄우고 [다시 시도]를 줍니다.

### 검사에 걸렸을 때

| 걸린 것 | 다시 받는 법 | 최대 | 끝내 실패하면 |
|---|---|---|---|
| 질문(확인 단계) | 까닭을 알려 주고 다시 | 2번 | 기본 질문 "왜 그렇게 생각했나요?", checks는 모두 think |
| 질문(문답 중) | 까닭을 알려 주고 **질문만 낼 수 있는 형식**으로 다시 | 2번 | 기본 질문 |
| 앞 질문 되풀이 | "앞에서 한 질문과 같음"을 알려 주고 다시 | 2번 | 기본 질문 |
| 세 줄 정리 | "판정은 그대로 두고 이 점만 고쳐" | 3번 | 판정 보류 + 기본 세 줄 |

까닭에는 "42자로 40자를 넘음 — 30자 안팎으로 줄일 것"처럼 고칠 정보를 넣습니다. 대신한 횟수는 `state.fallbacks`에 남겨 점검 페이지가 봅니다.

### 검사기(`guard.js`) 규칙

- **질문**
  - 비어 있지 않을 것
  - 40자 이내
  - `?`로 끝나고, **"요?"로 끝나는 존댓말**일 것
  - 한 문장일 것
  - 금지어(틀렸·정답은·오답)가 없을 것
- **확인**
  - checks가 3개이고, target은 0~2
  - mode와 대상의 짝
    - counter의 대상은 think
    - think가 있으면 reason이 아님
    - retry의 대상은 ok나 unsure가 아님
- **세 줄 정리**
  - 3줄이고, 줄마다 40자 이내
  - 금지어, 칸 이름 붙이기, "반례"라는 말, "학생이" 같은 3인칭이 없을 것
  - 셋째 줄은 "요?"로 끝나는 질문
  - 다시 볼 생각의 둘째 줄에 "처음에는·고쳤다" 같은 과정 말이 없을 것

## 6. AI 호출과 비용

- **호출** (`llm.js`)
  - `@anthropic-ai/sdk@1.13.0`을 jsdelivr에서 불러옵니다(`dangerouslyAllowBrowser`, 45초 제한, 재시도 1번).
  - 구조화 출력(`output_config.format: json_schema`)과 `effort`를 씁니다.

- **캐시 구조** (같은 차시 동안 반복되는 글은 캐시)
  - system: `[시스템 프롬프트, 오늘 차시 원문(cache_control)]`. 원문이 없으면 프롬프트 글만 씁니다.

  - **글의 차례를 바꾸지 마세요.** 단원 맥락을 system으로 옮겼더니 판단이 달라지는 퇴보가 있었습니다.
  - 캐시는 5분 동안 남습니다. 응답 형식(확인·다음·판정)마다 따로 캐시됩니다.
- **잰 비용 (소넷, 캐시 적용 뒤)**
  - 같은 차시의 두 번째 학생부터는 학생당 약 13~18원입니다. 캐시 전에는 50~145원이었습니다.
  - 차시마다 첫 학생은 캐시를 만드느라 약 90~130원이 듭니다.
  - 잰 조건(하루 2차시 × 2명)에서 약 200~280원이었습니다.
- **사용자님 사용 기준은 하루 최대 5명 × 2차시입니다.** 위 값으로 계산하면 다음과 같습니다(1년은 수업일 190일).
  - 소넷: 차시마다 첫 학생 90~130원 + 나머지 4명 52~72원이므로, 하루 약 280~400원, 1년 약 5만~8만 원입니다.

  - 학생과 학생 사이가 5분을 넘으면 캐시가 사라져 첫 학생 값이 다시 듭니다.

## 9. 해 보며 배운 것 (다음 방법에도 해당)

1. **흐름은 코드가, 글은 AI가.** 판정 시점·질문 수·실패 처리를 AI에게 맡기지 않습니다. AI는 형식이 정해진 JSON만 냅니다.
2. **검사에 걸리면 까닭을 알려 주고 다시 받습니다.** 같은 요청만 다시 보내면 같은 실수를 되풀이합니다. 까닭을 알릴 때 AI가 다른 단계로 넘어가 버릴 수 있으므로(질문 대신 판정), 다시 받을 때는 **응답 형식을 그 단계로만 좁힙니다.**
3. **목록보다 이름 붙은 칸.** 세 줄을 배열로 받으면 엉뚱한 내용을 채웁니다. 칸마다 이름과 설명(글자 수 포함)을 붙입니다.
4. **규칙 하나를 더하면 다른 곳이 바뀔 수 있습니다.** 반례 만드는 법을 넣자 맞는 말을 오개념으로 보는 퇴보가 생겼습니다(소넷 4/4).
   - 프롬프트를 바꾸면 반드시 실제 점검을 다시 돌립니다.
   - 이상하면 **이전 커밋 프롬프트로 같은 사례를 돌려 비교**합니다. `git show HEAD:…`를 `app/local/`에 꺼내 페이지에서 불러오는 식입니다.
5. **교과서 원문을 주면 AI가 깐깐해집니다.** 덜 자세한 말도 틀렸다고 보기 쉬워서, `think`는 "학생 문장 안에 틀린 주장이 실제로 있을 때만"으로 좁혔습니다.
6. **글의 차례가 판단을 바꿉니다.** 캐시를 위해 글을 옮길 때도 차례는 그대로 둡니다.
7. **정해 둔 모범 답만으로는 부족합니다.** 점검 학생이 늘 모범대로 깨달으면 흐름만 확인됩니다. 모름·고집·되묻기 같은 실제 학생 답을 꼭 넣습니다.
8. **퀴즈는 소크라테스식이 아닙니다.** 이름·숫자를 묻는 질문은 모르는 학생을 막다른 곳에 세웁니다. 학생 말에서 따라 나오는 결과를 묻습니다.
9. **반례 실마리는 두 곳에 쓰입니다.** AI 프롬프트의 예시와 선생님 도움말의 "이어서 물어볼 것"입니다. 질문 꼴로 써 두면 둘 다 좋아집니다.
10. **작업 환경 팁 (Windows)**
    - 데이터·테스트 일부 파일은 CRLF 줄끝입니다. 정확히 바꾸기 전에 줄끝을 확인합니다.
    - Python은 `-I -X utf8`로 실행합니다.
    - 브라우저 점검 스크립트는 한 번에 45초 안에 끝나게 나누어 기다립니다.
